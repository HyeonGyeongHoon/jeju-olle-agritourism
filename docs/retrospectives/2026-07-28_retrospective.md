## 0. 배경 (Background)
전날(2026-07-27) 세션은 단일 파일 `nodes.py` 의 패키지 분할, `AgentState` TypedDict 세분화, 프롬프트 품질 버그 3건 수정, 휠체어 하드 제약 Fail-Fast 갭 해소, 그리고 문화지식 스킵 및 시간/거리/난이도 하드 제약 반려 장치 구현으로 마감되었습니다.
오늘(2026-07-28) 세션은 시스템의 견고성을 강화하고, RAG 답변의 정밀성을 높이며, B2B 상품 기획자에게 걸맞은 고품질 보고서를 도출하는 것을 목표로 진행되었습니다. 사용자가 요청한 주요 핵심 개선 과제는 다음과 같았습니다.
- **기상 악화 반려 안전 장치 구현**: 기상 악화(DANGER) 상황이 감지될 시 RAG 검색을 사전에 우회하여 조기 반려(Fail-Fast) 가드레일이 작동하도록 연계.
- **Q&A 컨텍스트 오염 차단**: 일반 Q&A 질문 시 유사도 한계로 여름 작물(수박/참외 등) 정보가 혼입되어 답변이 오염되는 현상 근본 차단.
- **시스템 지시 라벨 유출 방지 및 중복 호출 개선**: 시스템 내부 지시 라벨(`[대상 코스 DB 실측 메타데이터]` 등)이 사용자 답변에 유출되는 버그를 해결하고, 도구 호출이 없는 상황에서 LLM 이 불필요하게 추가 호출되며 답변을 덮어쓰는 환각 현상 보완.
- **실제 안전 가이드 DB 연동**: 단순 하드코딩이 아닌, 실제 안전/에티켓 가이드 정보 DB(safety_etiquette_guide)를 연동한 정량적 준비물 가이드 구축.
- **B2B 준비물 가이드 추가**: 리포트 생성에 B2B 전용 준비물 및 가이드 생성 섹션을 신설하여 기획서 완성도 제고.
- **말투(문체) 교정**: 단순 정보 조회 시 답변 말투를 B2B 기획자 실무 설명체로 전면 교정.
- **LangSmith 를 활용한 LLMOps 오프라인 평가 및 모니터링 체계 구축**: 에이전트의 답변 품질을 일괄 평가하고 지속 모니터링할 수 있는 자동화 파이프라인 정립.
- **날씨 LLM JSON 파싱 예외 견고화**: 파싱 단계의 견고성을 더하여 시스템 신뢰도를 보장하고 회귀 방지 통합 테스트 보강.

## 1. 진행한 내용 (Key Achievements)

### (1) 기상 악화(DANGER) 반려 가드레일 구현 및 retriever 연계
- **문제**: 기상 악화 위험(DANGER) 상황이 추출되었음에도 RAG 검색 및 후속 LLM 연산을 전부 수행하여 리소스를 낭비하고 반려 처리가 비효율적으로 이루어졌습니다.
- **해결**: [safety.py](../../src/agent/nodes/safety.py) 의 `evaluate_safety_node` 에서 날씨 위험 분석 결과 위험 기상으로 판단될 때 `is_exit_early = True` 와 조기 종료 사유(`exit_reason`) 를 상태에 바인딩했습니다. [retriever.py](../../src/agent/nodes/retriever.py) 의 `retrieve_rag_node` 진입 단계에서 `is_exit_early` 가 설정되어 있다면 DB 쿼리와 pgvector 검색 등 무거운 연산을 전면 생략하고 `_build_fail_fast_result` 를 즉시 반환하도록 설계했습니다.
- **검증**: 기상 악화 테스트 상황을 입력했을 때, 불필요한 노드를 실행하지 않고 안전성 반려 로직이 깔끔하게 동작함을 확인했습니다.

### (2) Q&A 컨텍스트 오염 차단 (작물 정보 유출 차단)
- **문제**: "준비물이 뭐야?", "안전 수칙 알려줘" 등의 일반 Q&A 질의 시, 질문에 영농 맥락이 없음에도 유사도 임계치 한계로 인해 여름 작물(수박, 참외 등) 정보가 RAG 검색을 통해 흘러들어와 답변 오염을 유발했습니다.
- **해결**: [reporter.py](../../src/agent/nodes/reporter.py) 의 `quick_responder_node` 에서 질문 내용이나 검색 키워드에 농가 상생 테마(영농, 밭담, 상생, 체험 등) 관련 키워드가 매칭될 때만 문화지식을 조회하도록 명확한 게이팅 조건을 설정해 일반 Q&A 로의 오염을 원천 차단했습니다.
- **검증**: 단순 안전 수칙을 묻는 질문을 테스트했을 때 영농 문화 지식 조회가 완벽히 스킵되며 답변 품질이 깨끗하게 유지됨을 검증했습니다.

### (3) 시스템 라벨 유출 차단 및 tool_agent 조기 종료 (Early Exit) 보강
- **문제**: `[대상 코스 DB 실측 메타데이터]` 와 같은 템플릿 마커나 대괄호 형태의 시스템 지시 마크가 사용자 답변에 인용되는 사고가 발생했습니다. 또한, `tool_agent` 노드에서 이미 이전 노드인 `quick_responder` 가 완결성 높은 최종 답변(`final_response`) 을 작성해 두었음에도, 도구 호출이 없는 빈 컨텍스트로 LLM 을 무의미하게 추가 호출하여 이전 답변을 지우거나 덮어쓰며 환각을 일으켰습니다.
- **해결**:
  - [quick_responder.md](../../src/agent/prompts/quick_responder.md) , [tool_agent.md](../../src/agent/prompts/tool_agent.md) , [tool_agent_fallback.md](../../src/agent/prompts/tool_agent_fallback.md) 내 부정 프롬프트(Negative Prompt) 지시를 강화해 대괄호 시스템 라벨 유출을 전면 차단했습니다.
  - [tools.py](../../src/agent/nodes/tools.py) 의 `tool_agent_node` 에서 대기 중인 도구 호출(`pending_tool_calls`) 이 없고 기존 답변(`final_response`) 이 존재하면 LLM 을 재호출하지 않고 즉시 조기 리턴(Early Exit) 하도록 런타임 가드를 보강했습니다.
- **검증**: 특정 코스 Q&A 질의 시 도구 호출 없이도 `quick_responder` 의 온전한 답변이 훼손되거나 라벨 유출 없이 정상 출력되는 것을 확인했습니다.

### (4) 실제 안전 수칙/에티켓 DB 데이터 연동
- **문제**: 기존 안전 가이드나 에티켓 답변은 하드코딩된 일반론에 머물러 실질적인 지침을 제시하지 못했습니다.
- **해결**: [db_service.py](../../src/services/db_service.py) 에 제주 안전 및 에티켓 정보를 조회할 수 있는 `_fetch_safety_etiquette_guide` 데이터 접근 함수를 신설했습니다. 이를 [reporter.py](../../src/agent/nodes/reporter.py) 에 주입하여, 안전/수칙/준비물 등의 키워드가 매칭될 시 실제 가이드 DB(오전 9시 출발 권장, 비상 대피소 안내, 무료 단말기 대여 등)를 프롬프트 컨텍스트에 포함해 바인딩하도록 구현했습니다.
- **검증**: 질문 키워드에 따라 DB 에서 데이터를 조회하고 컨텍스트에 연동하여 답변이 생성됨을 확인했습니다.

### (5) B2B 기획서용 준비물 가이드 섹션 신설
- **문제**: B2B 상품 기획서 생성 시 실측 데이터 기반의 로컬 안전 및 탐방 가이드 섹션이 누락되어 기획서로서의 실무적 디테일이 부족했습니다.
- **해결**: B2B 전용 안전 탐방 가이드 및 준비물 생성 프롬프트인 [safety_guide.md](../../src/agent/prompts/safety_guide.md) 를 신규 설계하고, [reporter.py](../../src/agent/nodes/reporter.py) 의 `generate_report_node` 에 반영해 기획서 결과물에 `## 5. 🎒 로컬 안전 탐방 가이드 및 준비물` 섹션을 동적으로 합성했습니다. 이에 따라 기존 5번 섹션이었던 `## 5. 🛡️ Trust Tagging` 은 `## 6. 🛡️ Trust Tagging` 으로 한 칸 순연되었으며, 출처 리스트에 `제주 안전·에티켓 가이드 DB` 가 정확히 출처로 연동되도록 보완했습니다.
- **검증**: 통합 테스트 과정에서 생성된 기획서 마크다운 본문에 5번 안전 가이드 섹션이 정상적으로 들어갔으며, 이에 따라 6번으로 밀린 신규 Trust Tagging 영역과 출처 링크도 이상 없이 포맷팅됨을 확인했습니다.

### (6) 단순 정보 조회 시 B2B 기획자 말투(문체) 교정
- **문제**: 관광객이 아닌 B2B 기획자가 사용하는 툴임에도 불구하고, Q&A 에 대해 "~하세요", "~하는 것을 추천합니다"와 같은 여행객 타겟의 친근한 어투가 나오는 일관성 부족이 있었습니다.
- **해결**: [quick_responder.md](../../src/agent/prompts/quick_responder.md) 의 절대 규칙 2번을 개정하여 일반 여행객 대응조를 원천 금지하고, 기획자가 실무 현장에서 매뉴얼화할 수 있는 **"기획자/운영진 시점의 가이드 조율 톤"**(어미: ~ 필요, ~ 수립, ~ 권장 등)만을 사용하게 강제하고 전/후 예시 템플릿을 상세 추가해 교정했습니다.
- **검증**: 프롬프트 어조 개선 후 단순 안전 수칙에 관한 문의 시 여행자 안내 말투 대신 정돈된 개조식 기획서 가이드 톤으로 답변이 생성됨을 확인했습니다.

### (7) LangSmith 를 활용한 LLMOps 오프라인 평가 및 모니터링 체계 구축
- **문제**: 에이전트의 프롬프트 및 내부 로직 변경 시 전체 답변 품질에 미치는 영향도와 사이드 이펙트를 체계적으로 분석하고 정량적으로 모니터링할 도구가 없었습니다.
- **해결**: [evaluate_agent.py](../../scripts/evaluate_agent.py) 스크립트를 신규 구축하여 오프라인 평가 파이프라인을 완성했습니다.
  - **데이터셋 자동 동기화**: 질문과 모범답안 쌍으로 이루어진 `jeju-olle-docent-eval-dataset` 데이터셋을 선언하고, LangSmith 플랫폼에 업로드 및 동기화할 수 있도록 구현했습니다.
  - **에이전트 런타임 래핑**: LangGraph 에이전트의 `agent_runtime` 을 래핑하여 최종 응답 필드(`final_response` 또는 `docent_answer`) 를 추출 및 수집하도록 predict 함수를 정의했습니다.
  - **배치 평가 및 로깅**: LangSmith 의 `evaluate()` API 를 호출해 평가 실험(Experiment) 을 일괄 수행하고, 그 결과를 LangSmith 웹 대시보드로 실시간 추적할 수 있도록 모니터링 링크 연동을 완료했습니다.
- **검증**: 스크립트 실행 후 데이터셋 업로드와 배치 평가가 정상 수행되며 실시간 모니터링 가능한 실험 웹 링크가 터미널에 생성됨을 검증했습니다.

### (8) 날씨 API JSON 파싱 견고화 및 테스트 코드 보완

## 2. 잘된 점 및 배운 점 (Key Learnings & Successes)

- **LLM 의 답변 덮어쓰기 현상 제어**: LangGraph 환경에서 각 노드(특히 tool_agent 등 후속 노드) 가 이전 노드(`quick_responder` ) 의 우수한 출력을 단순히 빈 컨텍스트 호출로 덮어써서 망가뜨릴 수 있다는 점을 실감했습니다. 불필요한 LLM 호출 자체를 막는 조기 리턴(Early Exit) 조건 가드를 추가하는 것이 시스템의 효율성과 일관성 유지에 강력한 해법이 됨을 배웠습니다.
- **도메인 룰 결합 RAG 필터링의 파워**: 벡터 검색 유사도 임계치에만 전적으로 의존하는 것은 한계가 뚜렷합니다. 키워드 분석을 통해 영농 맥락 여부를 파악한 뒤 문화지식 조회를 게이팅하는 로직을 결합한 것이 단순 Q&A 가 다른 작물 정보로 인해 오염되는 버그를 잡는 데 결정적인 역할을 하였습니다.
- **B2B 대상 정렬의 중요성**: 에이전트 시스템은 사용 타겟에 따라 출력의 형태나 말투가 명확히 분리되어야 함을 깨달았습니다. 프롬프트 내에 단순히 말투를 변경해 달라는 식의 서술을 넘어 구체적인 Before/After 예시와 명사/개조식 어미 강제 등을 제공할 때 LLM 이 가장 확실하고 결정론적으로 동작한다는 교훈을 얻었습니다.
- **API 응답 파싱 시 정규식 가드의 유용성**: 외부 LLM 기반 API 응답을 JSON 으로 파싱할 때 백틱이나 주석 등 예기치 않은 문자들이 파싱 오류를 유발할 수 있습니다. 중괄호 범위를 정규식으로 먼저 슬라이싱해 주는 단순한 장치가 전체 시스템의 견실성(Robustness) 을 획기적으로 올려주었습니다.
- **LLMOps 기반 정량 평가 기반 도입**: 단순 수동 품질 확인이 아닌, 정형화된 오프라인 평가 데이터셋과 LangSmith 배치 테스트 파이프라인을 구축함으로써 코드나 프롬프트 변경이 유발하는 사이드 이펙트를 체계적으로 분석할 수 있는 인프라가 마련되었습니다.
